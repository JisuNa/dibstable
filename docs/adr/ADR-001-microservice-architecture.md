# ADR-001: 아키텍처 스타일 — 그린필드 마이크로서비스 채택

- **상태**: 승인
- **날짜**: 2026-07-19
- **관련 장**: 1장 (모놀리식 지옥에서 벗어나라)

## 문제

DibsTable(식당 예약 & 예약금 결제 플랫폼)을 어떤 애플리케이션 아키텍처 스타일로 구축할 것인가.

## 강제 조항

- **학습 목표가 최우선**: 《마이크로서비스 패턴》 1~13장의 패턴을 실제 동작하는 코드로 전부 실습해야 한다. 사가·CQRS·이벤트 소싱·게이트웨이는 서비스 경계가 실재해야 의미가 있다.
- **책의 권고와 상충**: 저자는 "신규 프로젝트는 모놀리스로 시작하라"(p.49)를 명시한다. 이베이·아마존 모두 모놀리스에서 출발했다.
- **1인 개발·운영**: 분산 시스템의 운영 가동부(브로커·서비스별 DB·게이트웨이)를 혼자 감당해야 한다.
- **품질 요건**: 예약 오픈 스파이크(확장성), PG 장애 격리(결함 격리), 좌석 초과 예약 0건(정합성) — [requirements.md](../requirements.md) 3절.
- **로컬 리소스**: 전체 스택이 개발 머신 docker-compose에서 기동 가능해야 한다.

## 해법

**그린필드 MSA를 채택한다.** 확장 큐브의 Y축(기능 분해)을 적용해 비즈니스 능력별 서비스로 구성하고(경계 확정은 2장), 각 서비스는 다음 정의를 만족해야 한다:

> **서비스 = 독립 배포 가능 + 자체 DB 소유 + 응집된 책임** (1.4절)

의도적으로 책의 "모놀리스 우선" 권고에 역행한다. 이 프로젝트의 산출물은 서비스가 아니라 **패턴 실습 경험**이므로, 모놀리스로 시작하면 학습 지형(분산 트랜잭션·분산 쿼리 문제) 자체가 생기지 않는다. 이 트레이드오프를 인지하고 선택했음을 기록한다.

## 결과 맥락

- **장점**: 서비스 독립 배포·확장, PG 장애의 결함 격리, 패턴별 실습 지형 확보, 모듈성이 API 경계로 구조적으로 유지됨.
- **단점**: 분산 시스템 복잡도(IPC·부분 실패·다중 DB), 1인에게 과한 운영 가동부, 로컬 리소스 부담, 초기 개발 속도 저하(책이 경고한 그대로).
- **새로 생긴 이슈** — 각 장이 해결한다:

| 이슈 | 해결 패턴 | 장 |
|---|---|---|
| 서비스 경계를 어디에 긋나 | 비즈니스 능력·하위 도메인별 분해 | 2장 |
| 서비스 간 통신·부분 실패 | RPI·회로 차단기·메시징·아웃박스 | 3장 |
| 여러 DB에 걸친 트랜잭션 | 사가·보상 트랜잭션 | 4장 |
| 서비스 내부 로직 구조 | DDD 애그리거트·도메인 이벤트 | 5장 |
| 결제 감사 이력 | 이벤트 소싱 | 6장 |
| 여러 서비스에 흩어진 조회 | API 조합·CQRS | 7장 |
| 외부 클라이언트 노출 | API 게이트웨이·BFF | 8장 |
| 서비스 간 계약 검증 | 계약 테스트·컴포넌트 테스트 | 9~10장 |
| 보안·구성·관측성 | JWT·외부화 구성·관측성 6패턴 | 11장 |
| 패키징·배포 | 컨테이너·(선택) k8s | 12장 |
| 신규 기능 추가 방식 | 새 기능을 서비스로·ACL | 13장 |

## 연관 패턴

- **대안 — 모놀리식 아키텍처 (기각)**: 1인 신규 프로젝트에는 객관적으로 더 옳은 선택이나, 학습 목표를 달성할 수 없어 기각. 실무에서라면 모놀리스로 시작했을 것이다.
- **후행자**: 위 표의 전 패턴.

## 수용 기준 (이후 장에서 지속 검증)

- [ ] 각 서비스는 단독으로 빌드·배포 가능하다.
- [ ] DB를 공유하는 서비스 쌍이 없다 (스키마 직접 접근 금지, API·이벤트로만 통신).
- [ ] 공유 라이브러리는 변경될 일 없는 안정 유틸(`Money`류)만 담는다 (2.1.3 공유 라이브러리의 함정).

## 리스크 감시 — 분산 모놀리스 징후 체크리스트

분해 실패의 최악 결과는 "모놀리식+마이크로서비스 단점만 결합한" 분산 모놀리스다. 매 장 완료 시 점검한다:

- [ ] 항상 함께 배포해야 하는 서비스 쌍이 생기지 않았는가?
- [ ] 한 요구사항 변경에 2개 이상 서비스 수정이 반복되지 않는가? (CCP 위반 신호)
- [ ] 다른 서비스의 변경 때문에 내 서비스가 계속 바뀌지 않는가?

> 조직 관점(역 콘웨이 전략, 8~12명 자율 팀)은 1인 프로젝트라 적용 대상이 아니며, 개념 학습으로 갈음한다.
