# ADR-003: 기술 스택 기준선

- **상태**: 승인
- **날짜**: 2026-07-19
- **관련 장**: 1장

## 문제

이후 12개 장이 올라탈 언어·프레임워크·빌드 도구 기준선을 확정한다.

## 강제 조항

- Kotlin + Spring Boot + Gradle은 사용자 확정 사항.
- 책 예제(자바+스프링) 이식성과 라이브러리 생태계(이벤추에이트, Resilience4j, Spring Cloud Gateway) 호환성이 좋아야 한다.
- 로컬 개발 머신에 JDK 21.0.8 LTS 설치 확인됨.

## 해법

| 항목 | 버전 | 근거 |
|---|---|---|
| JDK | **21 LTS** (toolchain + foojay 자동 프로비저닝) | LTS, 가상 스레드 사용 가능, 로컬 설치 확인 |
| Kotlin | **2.1.21** | 2.1.x 최신 패치 (2026-07 Maven Central 확인) |
| Spring Boot | **3.5.16** | 3.5.x 최신 패치. 4.x 대신 3.5.x를 선택 — 학습 자료·서드파티(스프링 클라우드 계열) 호환성이 검증된 안정선 |
| Gradle | **8.14.3** (wrapper) | Boot 3.5 공식 지원 범위. 로컬 CLI(9.x)와 무관하게 wrapper로 고정 |
| 버전 관리 | version catalog (`gradle/libs.versions.toml`) | 전 모듈 단일 소스 |

### 운영 규칙

- **브랜치**: `main` + 장별 브랜치(`chNN-<주제>`). 장 완료 리뷰 후 머지.
- **커밋 메시지**: `chNN: 요약` 형식.
- 이후 장의 인프라 선택(PostgreSQL·Kafka·Resilience4j 등)은 해당 장 ADR로 결정한다 — 1장에서 선점하지 않는다 (13장 교훈: "막대한 투자가 필요한 인프라 결정은 경험을 쌓은 후로 미뤄라").

## 결과 맥락

- **장점**: 검증된 조합으로 빌드 이슈 최소화, 책·커뮤니티 자료와 정합.
- **단점**: 최신(Boot 4.x, Kotlin 2.2.x) 기능 미사용. 학습 종료 시점에 업그레이드 ADR로 재검토 가능.
- **새로 생긴 이슈**: 없음.

## 연관 패턴

- **대안 — Spring Boot 4.x (보류)**: 신기능보다 생태계 안정성이 학습에 중요. 기각이 아닌 보류.
