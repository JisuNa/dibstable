# DibsTable 요구사항 정의

캐치테이블을 오마주한 **식당 예약 & 예약금 결제 플랫폼**.
《마이크로서비스 패턴》(크리스 리처드슨) 1~13장을 그린필드 MSA로 실습하는 학습 프로젝트다.

> 1장의 핵심 논지를 따른다 — **아키텍처를 결정하는 것은 기능 요건이 아니라 품질 요건(`~성`)이다.**
> 기능 요구는 어떤 아키텍처로도 구현할 수 있지만, 아래 품질 요구가 MSA 채택의 실질적 이유다 ([ADR-001](adr/ADR-001-microservice-architecture.md)).

## 1. 액터

| 액터 | 설명 |
|---|---|
| 고객 | 식당을 검색하고 예약금을 결제해 좌석을 예약한다 |
| 사장님 | 식당·타임슬롯을 오픈하고 예약을 관리한다 |
| 시스템 | 인기 식당 랭킹 집계 |
| PG사 (외부) | 예약금 결제 승인·취소 — 토스페이먼츠 샌드박스 |

## 2. 기능 요구 (유스케이스)

| ID | 액터 | 유스케이스 | 비고 |
|---|---|---|---|
| UC-1 | 고객 | 식당 검색 (지역·업종·인기순) | 7장 CQRS 뷰 |
| UC-2 | 고객 | 타임슬롯 조회 (날짜·시간대별 잔여) | |
| UC-3 | 고객 | **예약 생성** — 슬롯 선점 → 예약금 결제 → 확정 | **핵심.** 4장 사가 |
| UC-4 | 고객 | 예약 취소 — 환불 정책 적용 | 4장 보상 사가 |
| UC-5 | 고객 | 내 예약 조회 (예약+식당+결제 통합 뷰) | 7장 CQRS 뷰 |
| UC-6 | 사장님 | 식당 등록·타임슬롯 오픈 (정원 설정) | |
| UC-7 | 사장님 | 예약 접수 확인·거절, 노쇼 표시 | 페널티는 범위 외 |
| UC-8 | 고객 | 웨이팅 등록 | **13장에서 신규 기능으로 추가** |

## 3. 품질 요구 (`~성`) — 아키텍처를 결정하는 요건

| 품질 속성 | 요구 | 실현 수단 (장) |
|---|---|---|
| **정합성** | 좌석 초과 예약 0건 — 돈이 걸린 최우선 불변 값 | 애그리거트 불변 값 강제·낙관적 잠금 (5장), 시맨틱 락 (4장) |
| **확장성** | 인기 식당 예약 오픈 순간의 동시 예약 폭주 처리 | Y축 분해 + X축 복제 ([scale-cube](architecture/scale-cube.md)), CQRS 읽기 분리 (7장) |
| **결함 격리** | 결제(외부 PG) 장애가 검색·조회를 죽이면 안 됨 | 서비스 분리 (2장), 회로 차단기 (3장), 비동기 메시징 (3장) |
| **가용성** | 동기 호출 체인 최소화 — 가용성은 관여 서비스 가용성의 곱 | 비동기 메시징·응답 후 마무리 (3장) |
| **감사성** | 결제·환불 전체 이력 보존 | 이벤트 소싱 (6장) |
| **배포성** | 서비스 독립 빌드·배포 | 모듈 경계 (2장), 컨테이너 (12장) |
| **테스트성** | 피라미드 기반 — 빠른 하부 다수, 느린 상부 최소 | 단위·계약 (9장), 통합·컴포넌트 (10장) |
| **관측성** | 분산 요청 추적·중앙 로그·지표 | 관측성 패턴 (11장) |
| **보안** | 게이트웨이 인증, 서비스 간 신원 전달 | JWT (11장) |

## 4. 범위 제외

리뷰·평점, 정산·포인트, **알림 전체**(발송·수신 기록 — 담당 서비스 없는 반쪽 기능이라 제거, 이벤트 구독 학습은 7장 search-service가 담당), 노쇼 페널티, 좌석 단위 배치(타임슬롯 정원만 관리), 다국어·타임존(Asia/Seoul 고정), 실 클라우드 배포(로컬 docker-compose까지 — 12장에서 재결정).

## 5. 공용 언어 (Ubiquitous Language) 시작

2장 DDD 분해의 입력이 되는 초기 용어집. 서비스 경계 확정 시 경계 컨텍스트별로 재정의한다.

| 용어 | 영문 | 의미 |
|---|---|---|
| 식당 | Restaurant | 예약 대상 매장 |
| 타임슬롯 | TimeSlot | 날짜+시간대+정원으로 정의되는 예약 단위 재고 |
| 선점 | Hold | 결제 완료 전까지 슬롯 정원을 임시 점유하는 행위 |
| 예약 | Reservation | 고객-슬롯-예약금이 묶인 계약. 상태 기계를 가짐 |
| 예약금 | Deposit | 예약 확정 조건이 되는 선결제 금액 |
| 확정 | Confirm | 결제 승인 후 예약이 유효해진 상태 |
| 웨이팅 | Waiting | 만석 시 대기열 등록 (13장) |
